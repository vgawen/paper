# RQ3 改进版结果（候选定位器 + POM 闭包 + 双口径）

**日期**：2026-11-23
**运行**：`LLM_MODEL=deepseek-v4-flash RB_CONCURRENCY=6`，n=414（449 中跳过 35，与旧批同口径）
**产物**：`realproj/results/reprobreak_e2e_v2.json`

## 1. 全池结果（n=414，与旧批可比）

| 臂 | 旧批（无候选/POM） | 改进版（候选+POM） |
|---|---|---|
| 规则臂 exact-match | 3.38%（14/414） | **3.38%（14/414，确定性不变）** |
| LLM 臂 exact-match | 7.25%（30/414） | **6.52%（27/414）** |

**诚实结论 1**：在全池上，候选定位器 + POM 闭包 **没有带来可测量的提升**（6.52% vs 7.25%，差异在 LLM 非确定性波动范围内）。原因见 §3。

## 2. 语义等价口径（新增）

全池 exact-match 会误杀"语义等价但写法不同"的修复（`getByTestId('x')` vs `[data-testid="x"]`）。但语义比对**只在 distinctive 锚点上成立**：

- 全池 414 条中，**115 条**的答案定位器是 distinctive 锚点（testId / 可见文本 / label，且长度足够）；
- 其中 **90 条**在旧测试中不存在等价形式（否则"修复后含等价定位器"恒真，无信息量）；
- 语义指标只在这 **90 条子集**上统计。

| 指标（语义子集 n=90） | 规则臂 | LLM 臂 |
|---|---|---|
| exact-match | 13.33%（12/90） | 26.67%（24/90） |
| **语义等价** | **14.44%（13/90）** | **33.33%（30/90）** |
| 增益 | +1.11pp | **+6.66pp（相对 +25%）** |

分仓（语义子集内，LLM 臂 exact → 语义）：

| 仓库 | n | exact | 语义 |
|---|---:|---:|---:|
| microsoft/playwright | 35 | 14 | 14 |
| tryghost/koenig | 31 | 8 | **14** |
| nasa/openmct | 24 | 2 | 2 |

**诚实结论 2**：语义等价口径在 distinctive 子集上把 LLM 修复率从 26.67% 提到 33.33%，**增益主要来自 koenig（8→14，+75%）**——该仓是语义锚点（文本/属性）断裂为主。exact-match 确实误杀了这类正确修复。

## 3. 为什么全池没有提升：59% 的池子是 CSS class 断裂

| 仓库 | 池量 | 语义口径适用 | 说明 |
|---|---:|---:|---|
| ghiscoding/angular-slickgrid | 245（59%） | **4** | `.slick-cell` 类 CSS class/XPath 断裂，无"语义锚点"可替换 |
| microsoft/playwright | 45 | 36 | testId/文本锚点为主 |
| nasa/openmct | 46 | 42 | — |
| tryghost/koenig | 78 | 33 | — |

**这是本轮最重要的发现，也印证了原论文的数字**：ReproBreak 池中只有 **12.2%（1172/9604）** 是语义锚值替换型断裂；端到端池里也只有 **28%（115/414）**。占 59% 的最大仓几乎全是 CSS class 断裂，候选定位器与语义口径在那里**在原理上就无从发挥**。

## 4. 对论文的写法建议

1. 主表仍报 exact-match（与 ReproBreak 文献可比）：3.38% / 6.52%；
2. **新增一张语义口径表**，明确标注子集 n=90 及筛选规则（distinctive 且修复前不含等价），报 14.44% / 33.33%；
3. 明确写出"改善集中在语义锚点子集（约 22% 的池），CSS class 断裂占 59% 且原理上不可语义修复"——这比只报 7.25% 更完整，也解释了为什么整体数字上不去；
4. 候选定位器/POM 闭包的负结果（全池无提升）如实报告为"对 CSS class 断裂无效"，不外推。
