# 安全性（召回保证）：形式化定义、假设与命题

> 本文回应评审意见 #1（召回率不可妥协）与 #2（副作用/间接依赖）。目标：把"本方法不会遗漏应执行的测试用例"从口号变成**可陈述、可证明、可经验验证**的命题。本文与论文方法/理论章节对应，代码侧由 `pipeline/src/outcome_oracle.mjs`（非循环真值）、`pipeline/src/statedep.mjs`（状态闭包）与 `experiments/run_safety_mutation.mjs`（变异验证）支撑。

## 1. 记号与定义

- 版本对：旧版本 `V_old`、新版本 `V_new`，变更 `diff`。
- 测试全集：`T = { t_1, …, t_n }`（已有 E2E 测试）。
- 变更实体集 `Δ`：本次 diff 触及的源码实体，多粒度并集——文件、函数、路由、组件、UI 语义节点（text / testId / role / aria / href / 事件 handler）。
- 覆盖映射 `cov : T → 2^E`：测试在 `V_old` 上实际触达的源码实体集合（`E` 为全体实体）。由逐用例插桩执行得到（见 `MAPPER.md`）。
- 测试结果 `outcome_V(t)`：测试 `t` 在版本 `V` 上的**可观测结果**，定义为二元组 `(status, fingerprint)`：
  - `status ∈ {pass, fail, error, absent}`（`absent` = 该版本中不存在此测试）；
  - `fingerprint` = 关键断言的可观测取值指纹（如断言的期望/实际值、可见文本、计数等），用于捕捉"都 pass 但断言观测值变了"的情形。

### 1.1 真正受影响集 `A*`（与选择器无关）

> 这是全文的"金标准"。它**不依赖任何选择算法**，只由测试在两个版本上的可观测行为定义。

```
A* = { t ∈ T : outcome_{V_old}(t) ≠ outcome_{V_new}(t) }
```

即：在 `V_old` 与 `V_new` 上可观测结果（状态或断言指纹）发生变化的测试。这些就是"**应当被执行、漏掉就是漏测**"的测试——因为只有执行它们，CI 才能观测到该变化（无论是真实回归还是预期行为变更）。

**为什么不用覆盖来定义 `A*`？** 现有 `oracle.mjs` 用 `selectByCoverage(cov_{V_new}, Δ)` 构造受影响集，与选择器同源 → Safety 近乎自证。`A*` 改用真实结果差异定义，**打破循环**，由 `outcome_oracle.mjs::buildAffectedByOutcome` 经验测得（记为 `A_obs`，见 §4）。

### 1.2 选择规则 `Sel`

本方法的选择是两路信号的并集（`selector.mjs::select`）：

```
SelCov = { t ∈ T : cov(t) ∩ Δ ≠ ∅ }          // 覆盖信号臂
SelUI  = { t ∈ T : src(t) 引用了 Δ 中的 UI 语义节点 }  // UI 语义信号臂
Sel    = SelCov ∪ SelUI
```

## 2. 安全性命题

> **定义（安全 / Safe RTS）**：一个选择规则是**安全的**，当且仅当 `A* ⊆ Sel`，即所有真正受影响的测试都被选中（召回率 = 1，不漏测）。

### 命题 1（覆盖臂即安全）

在以下假设下，`A* ⊆ SelCov ⊆ Sel`：

- **(H1) 确定性**：测试结果只由被执行的代码与固定输入决定，不受随机性、时间、并发顺序等非受控因素影响（无 flaky）。
- **(H2) 覆盖完备性**：`cov(t)` 记录了 `t` 在 `V_old` 上执行到的所有源码实体（插桩无遗漏，无动态加载/SSR 盲区）。
- **(H3) 变更实体完备性**：`Δ` 覆盖了本次 diff 引入的所有语义改动所在实体（粒度足够细，且改动确实落在被测应用源码内）。

**证明（逆否）**：设 `t ∉ SelCov`，则 `cov(t) ∩ Δ = ∅`，即 `t` 在 `V_old` 上未执行任何变更实体。由 (H2)，`t` 执行轨迹涉及的实体集合 `⊆ cov(t)`，故都不在 `Δ` 中；由 (H3)，所有语义改动都在 `Δ` 内，因此 `t` 路径上的代码语义在 `V_old`/`V_new` 间未变；由 (H1)，相同代码语义 + 相同输入 ⇒ `outcome_{V_old}(t) = outcome_{V_new}(t)`，即 `t ∉ A*`。取逆否得 `A* ⊆ SelCov`。又 `SelCov ⊆ SelCov ∪ SelUI = Sel`，得证。∎

**推论**：UI 语义臂 `SelUI` 只做并集（只增不减），因此**不可能破坏召回**；它的作用是在覆盖粒度过粗（例如一个大文件被多测试触达）时提升 Precision，并为修复/生成提供 UI 锚点，而非用于保证 Safety。这与"宁可多跑也不漏"的工程取向一致：召回由 `SelCov` 保证，`SelUI` 锦上添花。

### 2.1 把"宁可多跑不漏"编码进规则

当对召回的信心高于对成本的敏感度时，本方法**总是包含整个 `SelCov`**，不做任何"看起来不太相关就剔除"的裁剪。Precision 的提升只能通过更细的 `Δ` 粒度获得，**绝不以牺牲 `SelCov` 中的测试为代价**。

## 3. 假设何时失效（诚实边界）

| 假设 | 失效场景 | 后果 | 处理 |
|---|---|---|---|
| H1 确定性 | flaky 测试、时间/并发相关 | 结果差异并非由 diff 引起 → 污染 `A_obs` | 多次重跑取稳定结果；flaky 单列，不计入主 `A_obs`（见 §4） |
| H2 覆盖完备 | 动态 import、SSR、未插桩第三方代码 | `cov(t)` 漏记实体 → 可能漏选 | 插桩覆盖率自检；对覆盖盲区的实体做**保守纳入**（路由/组件粒度兜底） |
| H3 实体完备 | 配置/数据/环境驱动的语义改动；**副作用**经由共享状态间接影响 | 语义改动不在 `Δ` 内 → `A* ⊄ SelCov` | **副作用情形交 §5 的状态依赖闭包专门处理**；配置/数据变更纳入 `Δ` 的扩展定义 |

> 关键诚实点：**命题 1 的安全性是"条件安全"**（在 H1–H3 下）。论文必须显式陈述这三个假设，并用 §4 的经验真值检验它们在实践中是否被违反、违反时方法是否仍不漏。

## 4. 经验召回验证（非循环）

代码：`pipeline/src/outcome_oracle.mjs`、`experiments/run_safety_mutation.mjs`。

1. **观测真值 `A_obs`**：在 `V_old` 与 `V_new` 上**全量**执行测试，用 `buildAffectedByOutcome` 取结果（status/fingerprint）发生变化的测试集合。这是 `A*` 的经验实例，**与选择器无关**。
2. **经验安全度** `SafetyEmp = |Sel ∩ A_obs| / |A_obs|`（`safetyEmp`）。目标 **= 1.0**。
3. **漏选审计**：任何 `A_obs \ Sel ≠ ∅` 的个案逐条写入 `out/safety_misses.json`，并归因到 H1/H2/H3 哪条失效（flaky？覆盖盲区？副作用？），论文如实分析，**不得掩盖**。
4. **覆盖臂单列**：同时报告 `SafetyEmp(SelCov)`，用以支撑命题 1（"覆盖臂即安全"）的经验成立。

### 4.1 变异增强（扩大真值规模）

自然 diff 下 `A_obs` 可能偏小、统计力不足。`run_safety_mutation.mjs` 对 `Δ` 中实体注入小型语义变异（改文案/属性/分支条件），重跑全量得到 `A_obs^{mut}`，在更大规模的"应被影响"样本上检验 `SafetyEmp = 1`。这给召回保证提供主动、可控的压力测试。

## 5. 副作用 / 间接依赖（评审意见 #2）

> **结论：导师假设成立。** 存在测试 `t`，`cov(t) ∩ Δ = ∅`（不直接触达变更代码），但 `t` 经由**共享系统状态**与受影响测试耦合，从而间接受影响。这正是 H3 失效的典型形态，命题 1 不再覆盖，需要扩展。

### 5.1 形式化

- 状态资源集 `R`：localStorage / sessionStorage / cookie / 全局变量 / 后端持久化表 / 外部服务端点等。
- 读写足迹 `rw : T → 2^{R × {read, write}}`：测试运行期对资源的读/写记录（由运行期 hook 采集）。
- **状态依赖关系** `t_i ⤳ t_j`：存在资源 `r`，使 `t_i` 写 `r` 且 `t_j` 读 `r`（数据流依赖），或执行序上 `t_i` 先于 `t_j` 且二者共享 `r`（顺序耦合）。

### 5.2 安全闭包

```
SelClosed = 闭包(Sel) = Sel ∪ { t : ∃ s ∈ (Sel ∩ A*), t 与 s 在 ⤳ 关系下共享资源 }
```

即把与"已选且受影响测试"共享状态者保守纳入。代码：`statedep.mjs::buildStateGraph` 构图、`closeSelection` 取闭包，选择器以可选开关 `--state-closure`（默认开，体现保守取向）接入。

### 命题 2（放宽 H3 后的安全性）

在 (H1)(H2) 成立、但允许副作用（放宽 H3）的前提下，若状态足迹 `rw` 完备（运行期 hook 无遗漏），则 `A* ⊆ SelClosed`。

**论证要点**：放宽 H3 后，`t` 受影响有两种来源——(a) `t` 直接执行变更实体（被 `SelCov ⊆ Sel` 捕获，同命题 1）；(b) `t` 经共享状态间接受影响，则必存在资源 `r` 与受影响路径相连，`t` 通过 `⤳` 与某 `s ∈ Sel ∩ A*` 共享 `r`，被闭包纳入 `SelClosed`。两种来源都被覆盖。代价是 Reduction 下降——这是"召回不可妥协"下可接受的权衡。∎

> **代价量化**：`run_sideeffect.mjs` 在注入副作用场景下对比 naive 文件级覆盖（漏 `t`）与 `SelClosed`（纳入 `t`），用 §4 的 `A_obs` 证明 `t ∈ A_obs`，并报告两者的 `SafetyEmp` 与 Reduction 差异。
