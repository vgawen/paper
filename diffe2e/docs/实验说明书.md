# DiffE2E 实验说明书

> 面向**代码变更感知的 Web 应用端到端回归测试用例选择与生成**方法的实验手册。
> 本文档是「按图索骥」式的操作说明：每个实验**验证什么、需要什么、怎么跑、产出什么、怎么读结果、验收标准**一应俱全，配合 `REPRODUCE.md`（一键复现）与 `EXPERIMENT_REPORT.md`（结果汇总）使用。
>
> 适用读者：论文作者（复跑/补数）、答辩评审（核实结论）、复现者（一键重跑）。

---

## 0. 研究问题与方法概览

方法是一条**五步闭环**：`代码 diff → 语义信号 → 选择 → 运行/修复 → 缺口生成`。核心是一个**测试↔代码映射器**（二部索引），把源码变更实体映射到受影响的 E2E 用例。

| 编号 | 研究问题 | 实验落点（脚本） |
|---|---|---|
| RQ1 | 基于「V_old 覆盖映射 + diff」能否**最小且安全**地选出相关 E2E 测试？ | `run_rq1.mjs` + `analyze.mjs` |
| RQ2 | 对覆盖**缺口**（新增路由/无测试）能否**生成**可执行、变更相关的用例？ | `run_rq2.mjs`（+ 人工/LLM 语义有效率） |
| RQ3 | 对选中的**失效**用例能否分类过时类型并**自动修复**复用？ | `run_rq3.mjs` + ReproBreak 子实验 |
| RQ4 | `T_select + T_run(Sel)` 是否**远小于** `T_full`（净收益）？ | `run_rq4_cost.mjs`（需真实项目 adapter） |

导师评审追加的三条硬指标（v3）：

| 编号 | 指标 | 实验落点 |
|---|---|---|
| 召回保证 | 用**与选择器无关**的「结果差异 oracle」验证 `SafetyEmp`，并给出可证明的安全性论证 | `run_rq1.mjs`（SafetyEmp）+ `run_safety_mutation.mjs` + `docs/SAFETY.md` |
| 副作用情形 | 共享状态导致的间接依赖被显式建模并保守纳入 | `run_sideeffect.mjs` + `pipeline/src/statedep.mjs` + `docs/SAFETY.md §5` |
| 净收益量化 | `NetSaving`、盈亏平衡点、时间以外资源 | `run_rq4_cost.mjs` + `docs/COST_MODEL.md` |

**贯穿全程的无信息泄漏纪律**：选择只用 `V_old` 覆盖 + diff；`V_new` 全量跑仅用于构造 oracle，**不参与选择**。修复的输入只能是「旧（断裂）测试 + 应用源码 old/new diff」，`new_locator` 与新测试文件**只能用于评估**。

## 1. 环境与前置依赖

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | ≥ 24 | 用到内置 `node:test`、ESM | 
| Playwright | `@playwright/test` ^1.49 + Chromium | `npx playwright install chromium` |
| Python3 | 标准库 `sqlite3` | 仅 ReproBreak 执行验证版 DB 导出需要（CSV 版不需要） |
| git | 任意近版本 | 受控主体逐 commit replay 依赖 tag checkout |
| LLM API key | **可选** | 不设则走**确定性 stub**；设 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` 走真实模型 |

依赖安装（仓库已随附 `pipeline/`、`subject/base/` 的 lockfile）：

```bash
cd diffe2e
npm install
npx playwright install chromium
```

> **无 key 也能跑完整条链**：生成/修复在无 key 时用确定性 stub，可测「可执行率 / 变更相关率 / 修复成功率」；只有「语义有效率」需要人工或真实 LLM 判定。

## 3. 一键复现（最小可写论文路径）

按下列顺序执行即可产出 RQ1–RQ3 + 召回 + 副作用 + ReproBreak 的全部定量结果与汇总报告。**全程零外部依赖、无需 LLM key。**

```bash
cd diffe2e

# 0) 单元测试（纯函数核心，应全绿）
cd pipeline && node --test && cd ..
cd experiments && node --test && cd ..

# 1) 构造受控主体 25-commit 历史
node subject/history/seed.mjs

# 2) RQ1 选择 + 非循环召回 + 统计图
node experiments/run_rq1.mjs
node experiments/analyze.mjs

# 3) 召回保证强化实验（导师意见 #1）
node experiments/run_safety_mutation.mjs

# 4) 副作用 / 间接依赖（导师意见 #2）
node experiments/run_sideeffect.mjs

# 5) RQ2 生成 / RQ3 修复
node experiments/run_rq2.mjs
node experiments/run_rq3.mjs

# 6) C1 闭环（语义 UI Diff 驱动整条链）
node experiments/uidiff_loop.mjs        # 静态，真实 JSX
node experiments/run_c1_dynamic.mjs     # 动态，真实 React 项目（自动还原）

# 7) 真实项目可插桩闸门 + ReproBreak 真实断裂数据
node realproj/gate.mjs
git clone --depth 1 https://github.com/rub-sq/ReproBreak realproj/clones/ReproBreak
node realproj/reprobreak.mjs

# 8) 汇总 → EXPERIMENT_REPORT.md
node experiments/aggregate.mjs
```

> **执行顺序说明**：步骤 2–8 的开发可并行，但 RQ3 依赖 RQ1 的产物 `out/rq1_dataset.jsonl`（读取选中/affected 集合）；`aggregate.mjs` 依赖 RQ1/RQ2/RQ3 + gate 的 json。故复跑务必保证 **RQ1 → RQ3 → aggregate** 的先后。

## 4. 实验逐项说明

下面每个实验按统一格式描述：**目的 / 输入 / 命令 / 产物 / 如何读结果 / 验收**。

---

### 4.1 受控主体构造（`subject/history/seed.mjs`）

**目的**：在隔离的嵌套 git 仓库 `subject/work/` 里脚本化构造 25 个 commit（`c00..c24`），每个打 tag 并记入 `manifest.json`，覆盖 8 类变更：`ui_text / logic / new_feature_gap / multi_file / locator_break / assertion_break / route / refactor_noise`。replay 引擎按 tag checkout 重放。

**输入**：`subject/base/`（初始应用）。
**命令**：`node subject/history/seed.mjs`
**产物**：`subject/work/`（git 仓库 + tag）、`subject/work/manifest.json`（每行 `{tag, type, desc, commit}`）。
**如何读**：`manifest.json` 是后续所有 replay 实验的「剧本」；变更类型用于 RQ1 的「按变更类型」分组统计。
**验收**：`work/` 存在 25 个 tag，`manifest.json` 25 行。重跑会重建，幂等。

> `subject/work/` 已 gitignored，不污染主仓库。

---

### 4.2 RQ1：测试选择 + 非循环召回（`run_rq1.mjs`）

**目的**：对 24 个变更过渡逐一：在 V_old 全量采逐用例覆盖 → diff 求变更文件 → 选择 `Sel`；在 V_new 全量跑构造 oracle；计算 ours 及多个基线的 Reduction/Safety/Precision。**关键升级**：额外用**与选择器无关**的「结果差异 oracle」`A_obs`（来自真实 pass/fail 翻转）计算 `SafetyEmp`，打破覆盖型 oracle 的自证循环，并审计漏选。

**对照臂 / 基线**：`ours(=dual) / coverage_only / uidiff_only / dual / retest_all / random_k / static_heuristic`。

**输入**：`subject/work/` + `manifest.json`。
**命令**：`node experiments/run_rq1.mjs`
**产物**：
- `out/rq1_dataset.jsonl`：每过渡一行（含 changed_files / selected / affected / affected_obs / safety_emp / 各方法 metrics）。
- `out/rq1_summary.{json,md}`：各方法均值 + 非循环 SafetyEmp 小节。
- `out/safety_misses.json`：漏选个案审计（`A_obs \ Sel`），正常应为**空数组**。

**如何读**（控制台末尾「Non-circular recall」段）：
- `SafetyEmp(ours)` 应 = **1.0**，`SafetyEmp(coverage_only)` 应 = 1.0（支撑「覆盖臂即安全」命题）。
- `misses` 应 = **0**。任一漏选都必须进 `safety_misses.json` 并在论文如实归因（H1/H2/H3 哪条假设失效，见 SAFETY.md）。

**验收**：每过渡覆盖归属干净；dual Safety 接近 1.0；SafetyEmp = 1.0、0 漏选。

> 紧接着跑 `node experiments/analyze.mjs`：对 ours 做 bootstrap 95% CI、对 ours vs 三基线做 Wilcoxon + Cliff δ + McNemar，产出 `out/rq1_stats.md` 与 `out/figs/rq1_metrics.svg`。

---

### 4.3 召回压力测试（`run_safety_mutation.mjs`）

**目的**（导师意见 #1）：自然 diff 的 observed-affected 样本可能太少、统计力弱。这里**主动注入**受控语义变异（翻转一个用户可见文案）作为已知 `Δ={F}`，重跑全量得到 `A_obs^mut`（真实结果差异，非覆盖自证），验证覆盖臂 `SelCov` 是否仍**覆盖每一个**结果发生变化的测试。

**协议**（对每个源文件 F）：① 基线全量跑；② 变异 F → 全量跑；③ `A_obs^mut` = 结果差异；④ `SelCov` = 基线覆盖触达 F 的测试；⑤ 断言 `SafetyEmp(SelCov, A_obs^mut)=1.0`；⑥ 用 git 还原 F（不提交）。

**命令**：`node experiments/run_safety_mutation.mjs [maxFiles=4]`
**产物**：`out/safety_mutation.json`（mean_SafetyEmp / all_safe / files_with_observable_effect）、`out/safety_mutation_misses.json`（应为空）。
**如何读**：`mean SafetyEmp=1.0`、`all_safe=true`、`misses=0`；`files_with_observable_effect>0` 表示确有非空有效样本（变异确实产生可观测影响）。
**验收**：`all_safe=true` 且 `total_misses=0`。

---

### 4.4 副作用 / 间接依赖（`run_sideeffect.mjs`）

**目的**（导师意见 #2）：证明经典覆盖型 RTS 在**测试间共享状态**时会漏。fixture `subject/sideeffect/`：生产者 A 访问 `/promo` 向共享后端写状态（`cov(A)={src/promo.js}`，**不触达** Δ）；消费者 B 访问 `/dashboard`（Δ=`{src/dashboard.js}`），读共享计数并断言 = 1，仅当 A 先跑才为真。

**实测三态对比**：B 的判定在 (全量) vs (naive 覆盖子集) vs (状态闭包子集) 下是否保真。

**命令**：`node experiments/run_sideeffect.mjs`
**产物**：`out/sideeffect.json`。
**如何读**：
- `coverage_only` 选出 B，**漏掉 A**（`coverage_only_includes_producer=false`）。
- naive 子集单独跑：B `pass→fail` **翻转**（`naive_faithful=false`，不保真）。
- `state_closed` 经 `statedep.mjs` 把 A 纳回（`state_closed_includes_producer=true`），B 保真（`closed_faithful=true`）。
- `conclusion` 应判定「naive 覆盖在共享状态副作用下不安全；状态闭包恢复保真」。

**验收**：`naive_faithful=false` 且 `closed_faithful=true`。

---

### 4.5 RQ2：覆盖缺口生成（`run_rq2.mjs`）

**目的**：对 `new_feature_gap` 类过渡（新增路由、无对应测试），用 `generateForGap` 生成 Playwright 用例，实跑度量**可执行率**与**变更相关率**（生成用例覆盖是否落到缺口文件）。语义有效率需人工/LLM 判定，故同时落盘待标注候选。

**命令**：
```bash
node experiments/run_rq2.mjs                       # provider=stub（默认）
DEEPSEEK_API_KEY=*** node experiments/run_rq2.mjs   # provider=deepseek（真实 LLM）
```
**产物**：`out/rq2_results.{json,md}`（含 `provider` / `execRate` / `relRate` / 每缺口行）、`out/rq2_to_annotate.jsonl`（待人工/LLM 评判的生成 spec）。
**如何读**：`executable-rate` 与 `change-relevant-rate` 越高越好；`semantic-validity` 标 NA（需后续标注）。
**验收**：stub 下两率出数；真实 LLM 下 diff 约束臂的变更相关率应明显更高（核心论点）。

> 语义有效率标注属**线下**工作：把 `rq2_to_annotate.jsonl` 发两名标注者盲标，再用 `cohenKappa`（`pipeline/src/stats.mjs`）算一致性，κ ≥ 0.6 为可接受（详见计划文档 Phase 2 与 `PROTOCOL.md` 约定）。

### 4.6 RQ3：失效用例修复（`run_rq3.mjs`）

**目的**：对 `locator_break / assertion_break` 类过渡：用 `staleness.classify` 三分类过时类型，用规则 `repair` 改写失效 spec，重跑验证，报告 `TargetedSetUsability`（修复前 vs 后）。

**输入依赖**：`out/rq1_dataset.jsonl`（取选中/affected 集合）——**须先跑 RQ1**。
**命令**：
```bash
node experiments/run_rq3.mjs                       # 规则臂（stub）
DEEPSEEK_API_KEY=*** node experiments/run_rq3.mjs   # 追加 LLM 修复臂
```
**产物**：`out/rq3_results.{json,md}`（修复成功率、过时分类、usability before→after）。
**如何读**：`repair success-rate` 与 `mean TargetedSetUsability: before → after`（应 0.0 → 1.0）；`staleness` 列应正确区分 STRUCTURAL_ONLY（定位重写）与 EXPECTATION_CHANGE（断言更新）。
**验收**：规则臂修复成功率与可用性提升出数；过时分类与变更性质一致。

### 4.7 ReproBreak 真实 locator 断裂（`realproj/reprobreak.mjs` + `gate.mjs`）

**目的**：用真实开源项目挖出的结构性 locator 断裂对（CSV ground truth）量化两件事——(E2) **Semantic UI Diff 可达性**（多少真实断裂是本方法 UI 信号可定位的语义锚值替换）；(E3) 给定 oracle 信号时**确定性改写器的精确匹配率**（隔离改写机制在真实语法上的正确性）。

**前置**：克隆数据集
```bash
git clone --depth 1 https://github.com/rub-sq/ReproBreak realproj/clones/ReproBreak
```
**命令**：
```bash
node realproj/gate.mjs        # 真实项目可插桩闸门报告（real/ 下的 cand_*）
node realproj/reprobreak.mjs  # 无 CSV 时打印 SKIPPED，不报错
```
**产物**：`realproj/results/gate.json`、`realproj/results/reprobreak.{json,md}`、`realproj/results/REPORT.md`。
**如何读**：E1 框架/类型分布；E2 `addressable` 占比（语义可达比例）；E3 `repair_rewriter.rate`（上界，假定信号已知）。改写失败样例暴露规则盲区，正是 LLM 增益空间。
**验收**：CSV 存在时给出可达性与改写率；DB（449 执行验证版）属后续工作，缺失时降级为 CSV 上界结果，不阻塞。

> **诚实定位**：E3 是上界（给定 oracle 信号）；端到端「diff→信号→修复」的信号检测精度需各 commit 源码 + 执行验证，属后续（计划文档 Phase 3 的 `reprobreak_e2e.mjs` 无泄漏端到端）。

### 4.8 C1 闭环：语义 UI Diff 驱动整条链

**静态**（`uidiff_loop.mjs`）：在真实 JSX（`pipeline/fixtures/App.{old,new}.tsx`）上做语义差分，驱动选择/生成/修复，验证「源码 diff ↔ 浏览器操作」桥接。产物 `out/c1_loop.{json,md}`。

**动态**（`run_c1_dynamic.mjs`）：在真实 React+Vite+Playwright 项目 `real/cand_coverage` 上**实跑** e2e，从真实 pass/fail 翻转构造 oracle，展示 uidiff 把选择精度从覆盖级 0.33 提升到 1.0，并实跑完成修复与生成（自动还原源码）。产物 `out/c1_dynamic.{json,md}`。

**命令**：
```bash
node experiments/uidiff_loop.mjs
node experiments/run_c1_dynamic.mjs
```
**如何读**：uidiff_only Precision = 1.0 vs coverage_only ≈ 0.33——证明 UI 信号在覆盖粒度过粗时的增益（与 RQ1 文件粒度主体互补）。

### 4.9 RQ4：净收益成本（`run_rq4_cost.mjs`）

**目的**（导师意见 #4 / `COST_MODEL.md`）：回答核心判据「`T_select + T_run(Sel)` 是否远小于 `T_full`」。两臂用**同一命令模板、同 `--workers`、同覆盖设置**；selected 多个 spec **一次性**传入单次调用；每臂重复 R≥3 次取 **median/IQR**；`T_select`（映射器增量更新 + diff 分析 + 选择计算）单独计时并并入 ours 总时。

**前置**：需要一个真实项目 **adapter.json**（字段：`name / repoDir / specGlob / testOneCmd（含 {spec} 占位符）/ covRel`；可选 `selectCmd` 用于真实计量 `T_select`）。受控主体不计真实 wall-clock；当前 `real/` 项目为浅克隆，真实多 commit replay 列为后续工作（见 `gate.mjs` 报告）。

**命令**：
```bash
# 用法: run_rq4_cost.mjs <adapter.json> "a.spec.ts,b.spec.ts" [workers] [repeats] [fullCount]
node experiments/run_rq4_cost.mjs experiments/real/adapters/<proj>.json "home.spec.ts,cart.spec.ts" 4 3 12
```
**产物**：`out/real/<proj>_rq4.json`（`T_full / T_run_sel / T_select / NetSaving / TimeReduction / SelectionTax / break_even / Reduction(cases)`）。
**如何读**：
- `Reduction(cases)`（少跑用例比例）与 `TimeReduction`（实际时间节省）**解耦报告**——强调「少跑 98% 不等于省 98% 时间」。
- `NetSaving = 1 − (T_select + T_run(Sel)) / T_full`，`break_even=true` 表示净收益为正。
- `SelectionTax` = 选择开销占 T_full 比例；若 adapter 无 `selectCmd`，报告会显式标注 `measured=false`，不假装选择免费。
**验收**：至少 1 个真实项目给出 `NetSaving > 0` 与盈亏平衡分析。

## 5. 关键指标定义

| 指标 | 定义 | 含义 |
|---|---|---|
| `Reduction` | `1 − |Sel| / |S|` | 少跑用例比例（越高越省） |
| `Safety`（覆盖型） | `|Sel ∩ Affected| / |Affected|`，Affected 来自 V_new 覆盖∩diff | 召回（**注意**：与选择器同源，易自证） |
| `SafetyEmp`（非循环） | `|Sel ∩ A_obs| / |A_obs|`，`A_obs` 来自真实 pass/fail 翻转 | **可信召回**，打破自证循环（导师意见 #1 核心） |
| `Precision` | `|Sel ∩ Affected| / |Sel|` | 选择精确性 |
| `TargetedSetUsability` | 选中且受影响的用例修复后可用比例 | RQ3 修复价值 |
| `NetSaving` | `1 − (T_select + T_run(Sel)) / T_full` | RQ4 真实净收益 |
| `Cohen's κ` | 两标注者一致性（剔除偶然一致） | RQ2 语义有效率 / RQ3 过时分类标注 |

## 8. 已知局限与降级路径

| 情形 | 降级行为 | 是否阻塞主结论 |

## 10. 故障排查（FAQ）

- **`run_rq3.mjs` 报找不到 `rq1_dataset.jsonl`**：先跑 `run_rq1.mjs`。
- **`aggregate.mjs` 报缺 json**：确保 RQ1/RQ2/RQ3 + `realproj/gate.mjs` 都已跑过。
- **Playwright 找不到浏览器**：`npx playwright install chromium`。
- **coverage 目录为空 / 用例混淆**：逐用例覆盖需串行（fixture 已按用例 start/stop 采集并落盘 `cov/<run>/<test>.json`）。
- **`reprobreak.mjs` 打印 SKIPPED**：未克隆数据集或 CSV 路径不对，设 `REPRO_BREAK_CSV` 或克隆到 `realproj/clones/ReproBreak`。
- **V_new 测试失败**：对 `*_break` 类过渡是**预期**的（断裂），不是错误；只有覆盖为空/缺失才是 replay 失败。
