# 一页说明：你要做的两件事

你不需要了解项目背景，也不需要写代码或跑测试。你只需要**读材料、做语义判断**，把结论填进两个文件。

## 任务一：30 条生成的端到端测试，判断“是否验证了这次变更”

- **材料与填写位置**：`02_RQ2_worksheet.md`，每节末尾的 `annotator2_yn=___`。
- **判什么**：这条测试是否真的打开应用，并操作或断言了**这次代码变更引入或改变的具体界面/行为**。四问全过才填 `y`：
  1. 它真的打开了应用，而不是用 `page.setContent(...)` 自己造了一个假页面？
  2. 它操作或断言的元素，和本节给出的“变更文件 + 应用源码 diff”对得上？
  3. 它的断言具体到“变更后的结果”，而不是只断言 body、页面或通用 header 可见？
  4. 如果这次变更不存在，这条测试会不会失败？
- **只填**：小写 `y` 或 `n`。`final` 留空。
- **不要**跑测试。自动执行结果与本题无关，你判的是语义相关性。

## 任务二：40 条已确认断裂的测试，判断“为什么断”

- **材料与填写位置**：`03_RQ3_worksheet.md`，每节末尾的 `human2=___`。
- **判什么**：这条断裂属于哪种过时。三个标签的判据与正反例见 `08_RQ3_LABELS.md`。
- **只填**：`STRUCTURAL_ONLY`、`EXPECTATION_CHANGE`、`SUSPECTED_REGRESSION` 三者之一，全大写、下划线。`final` 留空。
- **不要**跑测试。这些断裂已在旧版本上执行验证过；“断没断”不需要你判断。

## 遇到不确定怎么办

1. **先只用包内材料**：回到本节的应用源码 diff、完整旧测试块、断言级 diff（机械定位方式已遮蔽，语义锚可见）逐条核对。
2. **有材料但语义上两可**：按保守方向填。RQ2 填 `n`（宁可认为它没有验证变更）；RQ3 填 `SUSPECTED_REGRESSION`（宁可认为可能是真回归，不自动改写）。
3. **材料缺失、明显矛盾，或你读不懂旧测试意图**：**停下来，不要猜**，在 RQ3 每节已有的 `备注：` 里写明 `case_id` 与你缺什么，并联系协调者补齐材料后再判。不要用文件路径、commit 标题或“看起来像”来替代缺失证据。`备注` 只作说明，不能代替标签。
4. **不要为了“好看”改标签**：两可条目本身就是有效信息，按你的独立判断填即可。

## 什么时候必须停下（不要继续）

- RQ2 某节没有应用源码 diff，或 diff 里混进了测试文件；
- RQ2 的 spec 引用了包内看不到的 fixture、页面或组件，导致无法判断是否真的打开应用；
- RQ3 某节看不到完整旧测试块，或旧块里没有断言；
- RQ3 某节的应用源码 diff 为空，但 commit 主题看起来像行为变更；
- 你发现自己正在查仓库、搜结果文件、跑脚本或运行测试——立即停止，回到包内材料。

## 独立性

只依据包内材料判断。不要打开任何未在本包列出的文件，不要搜索代码仓库，不要运行测试或任何脚本。理由只有一句：包外的结果、标签、分组或统计会提前暴露答案，使你的独立判断失去意义。

## 时间与顺序

建议先完成任务一再做任务二；两者互相独立。每完成 5–10 条保存一次，避免丢失。

## 完成后怎么回传

1. 先确认收到的包未被改动：在本包目录执行 `shasum -a 256 -c SHA256SUMS`，每一行应为 `OK`。
2. 复制工作副本后再填，不要改原件：Markdown 方式复制 `02_RQ2_worksheet.md` 与 `03_RQ3_worksheet.md`；CSV 方式复制 `04_RQ2_fill_template.csv` 与 `05_RQ3_fill_template.csv`，文件名加上你的姓名拼音与日期。
3. 填完锁定后生成校验文件：对两份填写文件执行 `shasum -a 256` 与 `wc -c`，把结果和日期写入 `HANDOVER_CHECKSUMS_<姓名拼音>_<YYYYMMDD>.txt`。
4. 把两份填写文件与校验文件打包为 `annotation_return_<姓名拼音>_<YYYYMMDD>.zip`，发回协调者；不要回传本包原件。
